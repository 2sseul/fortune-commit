# todo-log

이 프로젝트는 중간고사 과제라서 README에 **"Todo 리스트의 변경 내역"**(처음 계획과 비교한 수정·테스트 후 변화·삭제·추가)과 **"사용한 스킬과 쓰인 방식"**을 반드시 실어야 한다. 또 작업 중에 일정한 간격으로 push해야 한다.
나중에 기억으로 되살리기는 어렵기 때문에, 일이 생긴 그 자리에서 `TODO_v2.md`에 남긴다. 이 스킬은 그 기록 방식을 하나로 맞춘다.

## 1. 처음 계획은 지우지 않는다

`TODO_v2.md`의 항목은 처음 계획의 기록이다. 바뀌어도 지우거나 덮어쓰지 말고, 바뀐 흔적이 보이게 표시한다. 그래야 README에서 "처음 계획 vs 실제"를 보여줄 수 있다.

| 상황 | 항목 표시 방법 |
|---|---|
| 끝냄 | `- [ ]` → `- [x]` |
| 새로 넣음 | 항목 끝에 `[추가 10-31]` |
| 내용이 바뀜 | 처음 문장은 남기고 뒤에 `→ [수정 10-31] 바뀐 내용` |
| 뺌 | `- [ ] ~~처음 문장~~ [삭제 10-31] 이유` |
| 써 보고 바꿈 | `→ [테스트 후 변경 10-31] 무엇을 해 보니 어떤 문제가 있어서 어떻게 바꿈` |

항목 번호(예: `v3.1-2-3`)는 바꾸지 않는다. 새 항목은 그 단계의 다음 번호를 쓴다.

## 2. 버전 끝의 기록란에 한 줄 남긴다

각 버전 섹션 맨 끝 `## v3.x 변경 내역·의견 기록`에 날짜 순으로 추가한다.

```
- 2026-10-31 [수정] v3.1-2-3: 처음엔 등급만 표시하려 했으나 → 등급별 문구 풀로 바꿈. 이유: 흉인데 좋은 문구가 나오면 어색해서 (사용자 결정)
- 2026-10-31 [테스트 후 변경] v3.2-1-2: 위젯에 🔥를 붙여 보니 좁은 width에서 운세와 겹쳐서, width < 400이면 숨김
- 2026-10-31 [아이디어] 순위표에 친구만 보기 → 다음 버전 후보
- 2026-10-31 [의견] 상점 카운터 색이 너무 어둡다 (사용자)
```

태그는 `[추가]` `[수정]` `[삭제]` `[테스트 후 변경]` `[아이디어]` `[의견]` 중 하나다. 누가 결정했는지(사용자 결정 / 사용자 요청 / AI 제안 승인)와 **이유**를 같이 적는다. 이유가 없으면 README에서 쓸 수 없는 기록이 된다.

사용자의 말투와 쉬운 한국어로 쓴다. 영어 개발 용어보다 "캐시 비우기", "쿠키가 열림" 같은 말을 쓴다.

## 3. 스킬을 썼으면 스킬 사용 기록에 남긴다

`TODO_v2.md` 맨 끝 `## 스킬 사용 기록`에 추가한다. README 4번(스킬)의 재료가 된다.

```
- 2026-10-31 `fortune-writer` · v3.1-2-1 · 대길 문구 40개 초안 작성 → 3줄 넘는 문구 2개를 스킬 규칙으로 걸러냄
- 2026-10-31 `code-review`(기존 스킬) · v3.2 배포 전 · 연속 기록 날짜 계산에서 시간대 버그 1개 발견
```

이 프로젝트 스킬(todo-log, fortune-writer, figma-to-site, pixel-skin, release-check)과 기존 스킬(code-review, security-review, claude-in-chrome 등) 모두 기록한다. todo-log 자신은 매번 적지 않고, 기록 방식을 바꿨을 때만 적는다.

## 4. 커밋한다

TODO 항목 하나가 끝나면 그 항목에 해당하는 파일과 `TODO_v2.md`를 함께 커밋한다. 커밋은 사용자 확인 없이 해도 된다.

- 형식: `feat:` / `fix:` / `docs:` / `test:` / `refactor:` + 한국어 설명. 무엇을 했는지 구체적으로 쓴다.
- Claude가 만들었다는 표시(Co-Authored-By 등)는 넣지 않는다.
- 예: `feat: 운세 등급(대길~흉)을 아이디+날짜 해시로 정하기 (v3.1-2-4)`
- `git add -A` 대신 바꾼 파일을 골라서 add 한다. `.env.local` 같은 비밀 파일이 섞이지 않게.

## 5. push는 항상 물어본다

push하면 Vercel에 자동 배포되므로, push 전에는 반드시 사용자에게 묻는다. 단계(예: `v3.1-2단계`)가 끝날 때마다 "v3.1-2단계까지 커밋 N개를 push할까요? push하면 바로 배포돼요."라고 묻는다. 과제가 "다 만들고 한 번에 push하지 말고 일정한 간격으로 push"를 요구하므로, 단계가 끝났는데 묻지 않고 넘어가지 않는다.

## 확인

끝나면 사용자에게 한두 줄로 알린다: 체크한 항목, 남긴 기록(태그), 커밋 메시지, push 질문.
