# release-check

버전마다 PRD_v2.md에 "완성 기준"이 있다. v2 때 배운 것은 **문서만 보고는 실제 환경 문제를 못 잡는다**는 것이다. (README에서는 JS가 안 됨, GitHub 기여가 UTC 날짜라 한국 0시에 안 잠김, 이미지 캐시 때문에 장착이 늦게 보임 등) 그래서 버전을 끝낼 때는 테스트 통과에서 멈추지 않고, 배포된 실제 사이트와 실제 GitHub 프로필에서 확인한다. 그리고 이 버전에서 계획이 어떻게 바뀌었는지 정리해서 README의 "Todo 변경 내역" 재료를 만든다.

## 1. 남은 일 확인

`TODO_v2.md`에서 이 버전의 체크 안 된 항목을 모은다. 남은 게 있으면 사용자에게 보여주고 "이건 끝내고 갈지, 다음 버전으로 미룰지, 뺄지" 묻는다. 미루거나 빼면 todo-log 규칙대로 `[수정]`·`[삭제]`로 표시한다. 그냥 체크하고 넘어가지 않는다.

## 2. 코드 점검

1. `npm test` — 실패하면 고치고 다시. 실패를 덮지 않는다.
2. `code-review` 스킬로 이 버전에서 바뀐 코드를 점검한다. (비교 기준: 이전 버전 태그 또는 버전 시작 커밋)
3. 포인트·구매·출석·보너스·굽기·로그인처럼 **포인트나 사용자 설정을 바꾸는 API**를 건드린 버전이면 `security-review` 스킬도 돌린다. 포인트를 부풀리거나 남의 설정을 바꾸는 구멍이 없어야 한다.
4. 찾은 문제는 고치고, 고친 내용을 todo-log로 기록한다.

## 3. 로컬에서 완성 기준 확인

`npm run dev`를 켜고 PRD_v2.md의 이 버전 **완성 기준을 한 줄씩** 확인한다. 브라우저 확인은 claude-in-chrome으로 하고, PC(1280px)와 휴대폰(390px) 크기를 둘 다 본다. 위젯은 `preview=locked/open`, `theme=dark/light`로 네 가지 모습을 본다.

로그인이 필요한 확인(구매, 장착, 출석)이나 실제 GitHub 활동이 필요한 확인(커밋하면 열림, 연속 기록)은 사용자에게 해 달라고 부탁하고, 무엇을 보면 되는지 구체적으로 알려준다.

## 4. 배포 (= push)

이 프로젝트는 GitHub `main`에 push하면 Vercel이 자동으로 배포한다. 그래서 배포는 push다.

- push 전에 사용자에게 묻는다: "v3.x 점검이 끝났어요. 커밋 N개를 push하면 바로 배포돼요. push할까요?"
- 새 환경변수가 필요한 버전이면(예: `ANTHROPIC_API_KEY`) push 전에 사용자에게 Vercel에 등록해 달라고 먼저 말한다. 값은 대화에 붙여 넣지 말라고 안내한다.
- 버전 태그(`v3.0` 등)를 붙일지도 같이 묻는다. 태그가 있으면 README에서 버전별 비교 링크를 만들 수 있다.

## 5. 배포된 사이트에서 다시 확인

배포가 끝나면 https://fortune-commit.vercel.app 에서 3번의 핵심 기준을 다시 확인한다. 로컬에서는 되는데 배포에서 안 되는 것(환경변수, Redis 연결, 캐시 헤더)이 있기 때문이다. 위젯 변경이 있는 버전은 2sseul의 GitHub 프로필(github.com/2sseul)에서 실제로 보이는지도 확인한다. 이미지 캐시 때문에 늦을 수 있다는 점을 감안한다.

## 6. 기록 남기기

1. `TODO_v2.md`의 완성 기준 점검 항목을 체크한다. 통과 못 한 기준은 체크하지 않고 이유를 적는다.
2. 이 버전 섹션 끝에 **"처음 계획 vs 실제"** 표를 쓴다. README 3번(Todo 변경 내역)에 그대로 옮길 수 있게.

   | 처음 계획 | 실제 | 왜 바뀌었나 |
   |---|---|---|
   | 운세 등급을 위젯에 표시 | 위젯은 등급 한 글자 배지만, 자세한 건 사이트에서 | 터미널 창이 너무 복잡해 보여서 (테스트 후 변경) |
   | (없음) | 장착 후 '캐시 비우는 중' 안내 추가 | 비우는 데 몇 초 걸려서 [추가] |

3. README에 쓸 만한 화면이 생겼으면 스크린샷을 `img/screenshot-*.jpg`로 저장할지 묻는다. (위젯 다크·라이트, 새 페이지 PC·모바일)
4. README의 "진행 상황" 표에서 이 버전 상태를 바꾼다.
5. todo-log 스킬로 기록과 커밋을 마무리한다.
