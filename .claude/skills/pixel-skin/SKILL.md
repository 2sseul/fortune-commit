# pixel-skin

fortune-commit의 쿠키는 **그림이 두 벌**이다.
- **사이트**: 듀오링고식 벡터 (`design/cookies/<이름>.svg`) — 큰 면 + 그림자 한 단계 + 하이라이트 하나, **얼굴(눈·입) 없음**
- **README 위젯**: 터미널 감성의 픽셀 (`design/cookies/pixel/<이름>.json`) — 벡터에서 **자동 변환**

손으로 픽셀을 찍지 않는다. 벡터를 한 번 그리면 픽셀은 스크립트가 만든다. 그래서 쿠키를 새로 그리거나 고친 뒤 픽셀 변환을 빼먹으면 위젯에서만 그 쿠키가 안 보이는 문제가 생긴다. 이 스킬은 그 빠뜨림을 막기 위한 순서다.

모든 그림은 오리지널이어야 한다. 다른 서비스·캐릭터 그림을 따라 그리지 않는다.

## 1. 벡터 쿠키 그리기 — `design/cookies/make.py`

1. 비슷한 쿠키를 먼저 찾아 본다 (`grep -n "'cat'" design/cookies/make.py` 등). 같은 방식으로 쓰면 된다.
2. 색이 새로우면 `P.update({...})`에 팔레트를 넣는다: `base`(앞 조각) `shade`(앞 그림자) `back`(뒤 날개) `back_shade` `fold`(접힌 안쪽, 가장 어두움) `hi`(하이라이트).
3. `ART.update({...})`에 `cookie(P['이름'], ...)`로 추가한다. 장식 자리:
   - `front_extra` / `back_extra`: 앞 조각·뒤 날개 **안에** 잘려 들어가는 무늬 (초코칩, 기호, 줄무늬)
   - `under`: 쿠키 **뒤**에 깔리는 것 (귀, 뿔, 속도선)
   - `over`: 쿠키 **위**에 올라가는 것 (모자, 반짝이, 소품)
   - `mid`: 뒤 날개와 앞 조각 사이 (열린 쿠키의 운세 쪽지)
4. 규칙
   - **얼굴 금지**: 눈·입은 물론, 점 두 개처럼 얼굴로 보이는 배치도 피한다. 실제로 세미콜론의 점 두 개, 파이썬의 흰 점, 선글라스가 얼굴처럼 보여서 고친 적이 있다.
   - 글자 대신 도형: 언어 쿠키는 `{ }`, `< >`, `#`, `λ`처럼 **기호를 선(stroke)으로** 그린다.
   - 이름 규칙: 업적·언어·밈은 영어 소문자(`owl`, `javascript`), 뽑기 쿠키는 `gacha-` 접두사, 상점 아이템 아이콘은 `item-` 접두사(픽셀 변환 안 함).
5. 실행: `cd design/cookies && python3 make.py` → "바뀐 것 N개: …"가 나온다. **내용이 바뀐 파일만 다시 쓰기 때문에** 다음 단계가 새 쿠키만 골라낸다.

## 2. 위젯용 픽셀 자동 변환 — `to_pixel.py --missing`

```
cd design/cookies && python3 to_pixel.py --missing
```

- 픽셀 지도가 없거나 벡터보다 오래된 쿠키만 변환한다. 쿠키 하나에 2초쯤. 바꿀 게 없으면 "바꿀 쿠키가 없어요"가 나온다.
- 하는 일: Chrome으로 자홍색 바탕에 크게 렌더 → 위젯 격자(쿠키 몸통 가로 약 27칸)로 줄임 → 그 쿠키의 색으로 정리 → 바깥 진한 테두리, 앞·뒤 사이 주름
- **앞 조각만 따로 한 번 더 렌더해서** 지도 글자를 대문자(앞 조각)/소문자(뒤 날개)로 나눈다. 위젯의 '갈라지는 애니메이션'이 두 조각을 따로 움직이기 때문에 꼭 필요하다.
- 결과: `pixel/<이름>.json` (팔레트 + 지도), `pixel/<이름>.svg` (미리보기)
- `--all`은 전부 다시(1분 넘게 걸림), 이름을 주면 그 쿠키만.
- 특별 처리가 있는 쿠키: `null`은 기본 쿠키 실루엣에 점선 테두리, `retro`는 원래 픽셀이라 변환 안 함.

## 3. 눈으로 확인 — `preview.py sheet`

```
python3 preview.py sheet <scratchpad>/check.png <이름 ...>
```

한 줄에 **사이트(벡터) · 위젯 다크 · 위젯 라이트**가 나온다. Read로 열어서 본다:
- 위젯 다크·라이트 둘 다에서 모양이 바탕에 묻히지 않는가 (흰색 장식은 라이트에서 특히)
- 작은 기호·장식이 픽셀에서 뭉개져 의미를 잃지 않았는가 → 뭉개지면 벡터에서 장식을 키우고 1단계부터 다시
- 얼굴처럼 보이는 곳이 없는가

새 쿠키를 사용자가 직접 고른 게 아니면 이 시트를 보여주고 의견을 받는다. 그림은 취향의 영역이다.

## 4. Figma에 올리기 — PNG로

Figma에는 **SVG를 그대로 올리지 않는다.** `clipPath`가 Figma에서 마스크 그룹이 되고, Figma 앱이 그걸 서버 스크린샷과 다르게 그려서 쿠키 조각이 벌어지거나, 그림자·선 기호가 사라진 적이 있다(MCP 스크린샷으로는 정상으로 보여서 놓침).

```
python3 preview.py figma <scratchpad>/png <이름 ...>    # 4배 크기 투명 PNG
```

- 새 쿠키: `upload_assets`로 PNG를 올린 뒤 그 프레임을 컴포넌트로 만든다 (`Cookie/Site/<이름>`, 높이 130).
- 이미 있는 쿠키를 고친 경우: 컴포넌트 안을 비우고 `upload_assets`의 `nodeIds`에 **그 컴포넌트 ID**를 넣어 이미지로 채운다. 컴포넌트 ID가 그대로라 화면에 놓인 쿠키들이 자동으로 바뀐다.
- 위젯용 픽셀(`pixel/<이름>.svg`)은 마스크가 없어서 SVG로 올려도 된다 (`Cookie/Widget/<이름>`).
- 확인은 사용자 화면 기준이다. 올린 뒤 사용자에게 Figma를 새로고침해서 봐 달라고 한다.

## 5. 목록에 등록 — `catalog.json`

`design/cookies/catalog.json`의 `cookies`에 한 줄 추가한다: `id`, `label`, `category`(기존·활동·시즌·언어·밈·특별·뽑기), `unlock`(해금 조건 문장), `data`(조건 계산에 필요한 데이터: `now`·`events`·`api`·`site`·`gacha`), 뽑기 쿠키면 `rarity`.
해금 조건은 지금 데이터로 계산되는지(`now`)부터 따진다. 새 데이터가 필요하면 사용자에게 알린다.

코드에 넣는 단계(위젯 렌더러가 `pixel/*.json`을 읽게, `src/unlocks.js` 규칙, 사이트 목록)는 TODO_v2의 v3.3 항목에서 한다.

## 6. 마무리

`todo-log` 스킬로 기록·커밋한다. 미리보기에서 고친 것(예: "점 두 개가 얼굴처럼 보여서 크게 바꿈")은 `[테스트 후 변경]`으로 남긴다. 커밋에는 `make.py`, 바뀐 `<이름>.svg`, `pixel/<이름>.json`·`.svg`, `catalog.json`을 함께 넣는다.
