# 🥠 fortune-commit

GitHub README에 붙이는 **오늘의 개발자 운세 포춘쿠키** 위젯입니다.
터미널 창 안의 픽셀 포춘쿠키를 누르면 쿠키가 갈라지면서 오늘의 운세가 나와요.

[![오늘의 운세](https://fortune-commit.vercel.app/api?user=2sseul)](https://fortune-commit.vercel.app)

- **커밋하고 열기**: 오늘 GitHub에 기여(커밋, PR, 이슈, 리뷰 등)를 하기 전에는 쿠키가 잠겨 있고, 기여하면 쿠키가 갈라지며 오늘의 운세가 나와요
- 같은 사람은 하루 종일 같은 운세, 사람마다 다른 운세 (GitHub 아이디 + 날짜로 결정)
- 매일 한국 시간 자정에 새 운세
- 한국어 / English, 다크 / 라이트 테마
- 설치는 이미지 한 줄 붙여넣기

## 사용 방법

아래 한 줄을 README에 붙여 넣고, `YOUR_GITHUB_ID`를 본인 GitHub 아이디로 바꾸세요. (아래 자동 전환 버전은 두 군데)
위젯을 누르면 fortune-commit 소개 페이지가 열려요.

```md
[![오늘의 운세](https://fortune-commit.vercel.app/api?user=YOUR_GITHUB_ID)](https://fortune-commit.vercel.app)
```

### 다크/라이트 모드 자동 전환 (추천)

GitHub를 다크 모드로 보는 사람에게는 다크 터미널, 라이트 모드로 보는 사람에게는 라이트 터미널을 보여줍니다.

```html
<a href="https://fortune-commit.vercel.app">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="https://fortune-commit.vercel.app/api?user=YOUR_GITHUB_ID&theme=dark">
    <img src="https://fortune-commit.vercel.app/api?user=YOUR_GITHUB_ID&theme=light" alt="오늘의 운세">
  </picture>
</a>
```

### 이렇게 보여요

| 오늘 기여 전 | 오늘 기여 후 |
|---|---|
| 안 열린 쿠키 + `오늘 커밋하면 열려요` | 쿠키가 갈라지며 오늘의 운세와 행운 아이템 |

- 위젯을 다는 커밋도 오늘의 기여로 세져서, **첫날은 바로 열려 있어요.** 다음 날부터는 커밋해야 열립니다.
- 커밋 후 열리기까지 몇 분 걸릴 수 있어요. (GitHub가 기여를 반영하는 시간 + 이미지 캐시 5분)
- 쿠키를 여는 '오늘 활동'은 **한국 시간 0시부터의 공개 활동**(push, PR·이슈 열기, 코드 리뷰, 새 저장소)으로 세요. 비공개 저장소 활동으로는 열리지 않아요. (GitHub 잔디는 UTC 날짜로 기록돼서, 한국 0시를 정확히 맞추려고 활동 시각이 남는 공개 이벤트를 써요)
- `user`를 빼면 잠금 없이 모두에게 같은 '그날의 공통 운세'가 나옵니다.

다른 테마와 언어 예시는 **[예시 갤러리](https://fortune-commit.vercel.app)** 에서 보고 바로 복사할 수 있어요.

## 🍪 쿠키 스킨 모으기

GitHub 활동으로 업적을 달성하면 새로운 쿠키 스킨이 해금돼요.

- **추천: [도감](https://fortune-commit.vercel.app/collection.html)에서 GitHub로 로그인**하고 해금한 스킨을 장착하세요. README를 고치지 않아도 위젯에 바로 적용되고, 장착 설정은 README의 `skin=`보다 항상 우선해요. 저장하는 건 GitHub 아이디와 장착한 스킨뿐이에요.
- 로그인 없이 쓰려면 [스킨 고르기 페이지](https://fortune-commit.vercel.app/skins.html)에서 고른 스킨이 들어간 코드를 복사해 README에 붙여도 돼요.

| 스킨 | `skin=` | 해금 조건 (올해, 기준 시간대) |
|---|---|---|
| 기본 쿠키 | `plain` | 처음부터 |
| 초코 쿠키 | `choco` | 기여 50개 |
| 말차 쿠키 | `matcha` | 기여 150개 |
| 황금 쿠키 | `gold` | 7일 연속 기여 |
| 고양이 쿠키 | `cat` | 커밋 100개 |
| 강아지 쿠키 | `dog` | PR 10개 |
| 토끼 쿠키 | `rabbit` | 코드 리뷰 10개 |
| 호박 쿠키 | `pumpkin` | 10월에 기여 10개 |
| 눈사람 쿠키 | `snowman` | 12월에 기여 10개 |
| 사슴 쿠키 | `deer` | 12월에 기여 30개 |
| 산타 쿠키 | `santa` | 12월 25일(크리스마스)에 기여 |

- 해금 전에는 기본 쿠키와 진행 상황(예: `skin = "cat 37/100 commits"`)이 보이고, 조건을 채우면 자동으로 그 스킨으로 바뀌어요.
- 조건은 올해 활동으로 계산하고, 한 번 해금한 쿠키는 해가 바뀌어도 계속 쓸 수 있습니다.
- 스킨 그림은 모두 오리지널이에요. 디자인 원본은 [`img/`](img/)에 있어요.

## 옵션

주소 뒤에 `&이름=값` 으로 붙입니다. 예: `...api?user=octocat&lang=en&theme=light`

| 옵션 | 설명 | 값 | 기본값 |
|---|---|---|---|
| `user` | GitHub 아이디. 아이디 + 날짜로 그날의 운세가 정해져요 | 아이디 | 없음 (모두에게 같은 공통 운세) |
| `lang` | 운세 언어 | `ko`, `en` | `ko` |
| `theme` | 터미널 색 | `dark`, `light` | `dark` |
| `tz` | 하루가 바뀌는 기준 시간대 | `Asia/Seoul`, `UTC`, `America/New_York` 등 | `Asia/Seoul` |
| `width` | 위젯 너비(px) | `400` ~ `800` | `495` |
| `radius` | 모서리 둥글기(px) | `0` ~ `30` | `10` |
| `hide_border` | 테두리 숨기기 | `true`, `false` | `false` |
| `skin` | 쿠키 스킨 (위 표 참고, 해금해야 적용) | `plain`, `choco`, `cat` 등 11종 | `plain` |
| `preview` | (테스트용) 기여 수와 상관없이 잠긴/열린 화면 보기 | `locked`, `open` | 없음 (실제 기여 수로 결정) |

잘못된 값을 넣어도 위젯이 깨지지 않아요. 숫자가 아니면 기본값, 범위를 벗어나면 가장 가까운 값을 씁니다.

## 이렇게 동작해요

- README에서는 JavaScript가 실행되지 않아서, 위젯은 서버(Vercel)가 그때그때 만들어 주는 **SVG 이미지**입니다.
- 쿠키가 갈라지는 움직임은 SVG 안의 **CSS 애니메이션**이에요.
- 위젯을 불러올 때마다 서버가 **GitHub GraphQL API**로 오늘 기여 수를 확인해서, 0개면 잠긴 쿠키를 보여줍니다. 확인에 실패하면 위젯이 깨지지 않도록 운세를 그대로 보여줘요.
- 운세는 난수가 아니라 `아이디 + 날짜`의 해시로 고르기 때문에, 언제 열어도 그날은 같은 운세가 나옵니다.
- 그림 파일 없이 쿠키도 코드(픽셀 지도)로 그립니다. → [`src/cookie.js`](src/cookie.js)

# 만들면서 돌아본 것: PRD와 TODO 리스트로 만든 바이브 코딩

## 1. 제작한 것 소개

**fortune-commit**은 GitHub 프로필 README에 붙이는 "오늘의 개발자 운세" 위젯과, 그 위젯을 꾸미고 관리하는 웹 서비스다. 핵심 아이디어는 **"오늘 커밋해야 포춘쿠키가 열린다"**는 것이다. 잔디를 꾸준히 심게 만드는 작은 동기를 운세라는 재미 요소로 주고 싶었다.

- 위젯: https://fortune-commit.vercel.app/api?user=octocat
- 사이트: https://fortune-commit.vercel.app

### 주요 기능

- **커밋하고 열기**: 매일 한국 시간 0시에 쿠키가 잠기고, 그날 GitHub에 공개 활동(push, PR, 이슈, 리뷰 등)을 하면 쿠키가 갈라지며 운세가 나온다. GitHub 잔디는 UTC 날짜로 기록되기 때문에, 한국 0시를 정확히 맞추려고 활동 시각이 남는 공개 이벤트로 오늘 활동을 센다.
- **나만의 오늘 운세**: 운세는 난수가 아니라 `아이디 + 날짜`의 해시로 고른다. 그래서 같은 사람은 하루 종일 같은 운세를 보고, 사람마다 운세가 다르다. 운세는 한국어·영어 105개씩이고, 지난 7일 활동과 주 사용 언어에 맞춘 문구, 행운 아이템(`lucky_status = "200 OK"` 같은 코드 스타일)도 나온다.
- **터미널 + 픽셀 쿠키 디자인**: README에서는 JavaScript가 실행되지 않으므로, 위젯은 서버가 그때그때 만들어 주는 SVG 이미지이고 쿠키가 갈라지는 움직임은 SVG 안의 CSS 애니메이션이다. 쿠키는 그림 파일 없이 코드(픽셀 지도)로 그렸다. 다크/라이트, 크기, 모서리, 언어, 시간대 옵션이 있다.
- **쿠키 스킨 11종**: 고양이(올해 커밋 100개), 호박(10월에 기여 10개), 산타(크리스마스에 기여) 같은 조건을 채우면 해금된다. 해금 전에는 위젯에 진행 상황(`cat 96/100 commits`)이 보이고, 한 번 해금한 쿠키는 해가 바뀌어도 계속 쓸 수 있다.
- **로그인과 도감**: GitHub로 로그인해서 도감에서 쿠키를 고르면, README를 고치지 않아도 위젯에 바로 반영된다. 다른 사람은 내 설정을 바꿀 수 없다.
- **포인트와 쿠키 상점**: 올해 기여 1개당 10점, 커밋한 날 사이트에서 쿠키를 열면 출석 30점이 쌓인다. 포인트로 스킨과 디저트 터미널 테마(딸기우유, 민트초코 등)를 사서 장착할 수 있다.
- **사이트**: 직접 그린 픽셀 빵집 장면이 첫 화면이다. 반죽이(마스코트)의 눈이 마우스를 따라오고, 접시 위 쿠키를 누르면 운세 쪽지가 나온다. 휴대폰에서는 아래 탭 막대로 앱처럼 쓸 수 있다.

### 만든 순서

| 버전 | 만든 것 |
|---|---|
| v1 | 터미널 + 픽셀 포춘쿠키 위젯, 아이디·날짜 기반 운세, 행운 아이템, 옵션, 커밋하고 열기 |
| v2.0 | 활동으로 해금하는 쿠키 스킨 11종과 진행 상황 표시 |
| v2.1 | GitHub 로그인, 도감, 장착하면 README 수정 없이 반영, 베이커리 콘셉트 메인 페이지 |
| v2.2 | 포인트와 쿠키 상점, 한 번 해금한 쿠키는 영원히, 휴대폰 화면 |

- 기술: Node.js, Vercel 서버리스 함수, SVG + CSS 애니메이션, GitHub GraphQL/REST API, GitHub OAuth, Redis
- 규모: 2일(2026-10-11 ~ 12), 커밋 50여 개, 자동 테스트 72개, TODO 항목 108개

## 2. 방법론의 장단점

### 어떻게 진행했나

1. **PRD를 먼저 썼다.** 개요, 문제, 사용자, 꼭 있어야 하는 기능, **만들지 않는 것**, 디자인, 기술 조건, **가정**, **열린 질문**, **완성 기준**으로 나누고, 맨 위에 AI에게 보내는 요청(요약 확인 → 질문 → 계획 제안 → 승인 후 작업, "만들지 않는 것"은 구현 금지)을 넣었다.
2. **PRD를 TODO 리스트로 쪼갰다.** 단계마다 "목표"와 "확인 방법"을 두고, 항목마다 근거가 되는 PRD 번호(`PRD #4-2`)를 달았다. 내가 직접 해야 하는 일은 **(직접)**으로 표시했다.
3. **TODO 맨 끝에 기록 섹션을 두었다.** 개발 중 생긴 `[아이디어]`, `[의견]`, `[수정]`을 날짜와 함께 계속 쌓았다.
4. 버전이 올라갈 때마다 PRD에 새 섹션(v2, v2.1, v2.2)을 추가하고 TODO를 새로 만들었다.

### 장점

- **범위가 안 흔들렸음.** "만들지 않는 것"에 포인트랑 상점을 적어 놨더니, v2.1 하면서 계속 생각나도 v2.2로 미룰 수 있었음. 덕분에 버전마다 그날 안에 끝낼 수 있었음. v1 때 "언제 멈춰도 돌아가는 순서"(운세 → 테마 → 행운 아이템 → 옵션 → 애니메이션 → 활동 반영)를 정해 둔 것도 같은 역할을 했음.
- **완성 기준이 그대로 테스트가 됐음.** "한국 자정 지나면 운세가 바뀐다"는 기준을 실제로 확인하다가, GitHub 잔디가 UTC 날짜라서 한국 0~9시에는 전날 커밋 때문에 쿠키가 열려 있는 버그를 찾았음. 기준이 없었으면 그냥 모르고 넘어갔을 듯.
- **AI가 멋대로 정하지 않았음.** PRD에 "열린 질문"이랑 요청문을 넣어 둬서, 애매한 건 만들기 전에 나한테 먼저 물어봤음. 가격표, 포인트 규칙, 해금 조건 같은 건 다 내가 골랐음.
- **대화가 끊겨도 이어서 할 수 있었음.** 대화가 길어져서 AI 기억이 요약돼도, TODO 체크 상태랑 기록 섹션만 보면 뭘 왜 바꿨는지 다시 알 수 있었음. 기록 섹션이 거의 "결정 기록" 역할을 했음.
- **어디서 나온 기능인지 추적이 쉬웠음.** TODO 항목 → PRD 번호 → 커밋 메시지(`feat:`, `fix:`)로 이어져서, 이 기능이 어떤 요구에서 나왔는지 거슬러 올라갈 수 있었음.
- **단계마다 돌아가는 결과물이 있었음.** 단계 끝날 때마다 테스트 → 커밋 → 배포를 해서, 중간에 멈춰도 쓸 수 있는 상태였음.

### 단점

- **디자인은 글로 정하기 힘들었음.** PRD 디자인 항목은 위젯만 다뤘고 사이트 디자인은 계획 없이 시작했음. 그래서 메인 페이지가 "AI가 만든 사이트 같음" → 베이커리 → 빵집 장면 → 스티커 스타일 → 구성 변경 → 픽셀 그림으로 여섯 번이나 바뀌었음. "이 사이트 느낌 좋다"고 한 걸 AI가 스타일로 알아들었는데 사실 내가 좋았던 건 "구성"이었던 것처럼, 글로는 의도가 잘 안 전해졌음. 반대로 내가 그린 픽셀 빵집 그림을 보여주니까 한 번에 원하는 대로 나왔음.
- **가정을 확인 안 하고 넘어갔음.** PRD에 "캐시 시간만 잘 정하면 GitHub 이미지 캐시는 괜찮다", "오늘 기여 수로 잠금을 판단한다"고 적었는데, 실제로는 캐시가 오래 남아서 직접 비워야 했고 기여 날짜는 UTC였음. 가정이 틀린 걸 다 만들고 나서야 알았음.
- **중간에 계획이 계속 늘어났음.** TODO 항목 중 14개가 "사용자 요청"이나 "추가 제안"으로 나중에 끼어들었고, v2.1은 5단계(메인 페이지)가 4단계(완성 점검)보다 먼저 들어가서 번호 순서가 꼬였음.
- **문서가 너무 길어졌음.** TODO는 380줄, PRD는 버전마다 덧붙여서 270줄이 됐음. 계획이랑 기록이 한 파일에 섞여서 "지금 뭐가 남았지?" 보려면 긴 기록을 다 뒤져야 했음.
- **체크했다고 확인된 건 아니었음.** 로그인이나 프로필 반영처럼 내 계정이 있어야 확인되는 건 AI가 체크할 수 없었고, "확인 방법"을 해 본 결과(언제, 뭘 봤는지)도 따로 안 남았음.
- **같은 내용을 여러 군데서 고쳐야 했음.** 해금 규칙을 "한 번 해금하면 영원히"로 바꿨을 때 코드, README, 스킨 페이지, 도감, PRD를 다 고쳐야 했음.

## 3. 개선이 필요한 점

1. **디자인은 그림으로 정의한다.** PRD에 참고 이미지와 간단한 시안을 넣고, 구현 전에 시안 2~3개를 비교해서 고른다. 말로 하는 디자인 요청은 "무엇이 좋은지(스타일/구성/색)"를 나눠서 적는다.
2. **가정마다 확인 방법을 붙이고 먼저 실험한다.** 외부 서비스의 동작(캐시, 시간대, API 지연)에 기대는 가정은 1단계에서 작은 실험으로 확인한 뒤 본 작업을 시작한다.
3. **새 요청은 대기열을 거친다.** 개발 중 떠오른 요청을 TODO 중간에 바로 끼우지 않고, "대기열"에 적어 두었다가 단계가 끝날 때 어느 버전에 넣을지 정한다. 번호 순서도 지켜진다.
4. **문서를 역할별로 나눈다.** PRD(무엇을, 왜), TODO(지금 할 일만), 결정 기록(DECISIONS.md, 날짜·결정·이유)으로 분리하면 각 문서가 짧아지고 현재 상태가 잘 보인다.
5. **완성 기준을 확인 가능한 형태로 쓴다.** 자동 테스트로 만들 수 있는 기준은 테스트로 만들고, 사람이 봐야 하는 기준은 "확인한 날짜와 증거(스크린샷 등)"를 남기는 칸을 둔다.
6. **값은 한 곳에서 정의한다.** 가격, 해금 조건 같은 값은 코드 한 곳에만 두고, 문서와 페이지는 그 값을 불러 쓰게 해서 고칠 곳을 하나로 줄인다.

## 4. 결론

처음에는 PRD와 TODO를 쓰는 시간이 코드를 바로 짜는 것보다 느리다고 생각했다. 하지만 AI와 함께 만들어 보니, 문서는 AI에게 일을 시키는 지시서이면서 내가 무엇을 원하는지 스스로 정리하는 도구였다. "만들지 않는 것"과 "완성 기준"을 적어 둔 덕분에 AI가 앞서 나가지 않았고, 하루 만에 실제로 배포되는 결과물을 만들 수 있었다.

동시에, 문서로 다 정할 수 없는 것도 분명했다. 디자인은 글로 몇 번을 설명해도 엇나갔지만 그림 한 장으로 바로 전달됐고, 시간대와 캐시 문제는 문서가 아니라 실제로 써 보면서 발견됐다. 바이브 코딩에서 사람의 역할은 코드를 직접 짜는 것보다 **무엇을 만들지 정하고, 결과를 직접 확인하고, 원하는 것을 정확히 전달하는 것**에 가깝다고 느꼈다.

작은 위젯 하나에서 시작해 로그인, 도감, 상점까지 있는 웹 서비스가 됐다. 내가 매일 커밋하게 만들려고 만든 쿠키가 실제로 내 잔디를 채우고 있다는 점이 가장 뿌듯했다. 다음에는 위의 개선점, 특히 디자인 시안과 가정 검증을 먼저 하는 방식으로 더 적은 되돌림으로 만들어 보고 싶다.
