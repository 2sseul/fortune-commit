## 1. 제작한 것 소개

### 무엇인가

잔디(GitHub 기여 그래프)를 꾸준히 채우는 일에 **작은 이유**를 하나 만들어 주는 서비스입니다.
README에 붙인 포춘쿠키는 매일 밤 0시에 닫히고, 그날 커밋을 해야 갈라지면서 오늘의 운세를 보여줍니다.
커밋이 쌓이면 쿠키가 해금되고, 포인트로 쿠키를 뽑거나 사서 위젯에 올릴 수 있습니다.

실습 과제(v2.2, `practice-submission`) 이후 이번 과제(v3)에서 커밋을 40개 넘게 더 쌓았습니다.

### 위젯 달기

포장해 가기에서 코드를 복사하거나, 아래처럼 붙이고 `YOUR_GITHUB_ID`만 바꾸면 됩니다.

```markdown
[![오늘의 포춘쿠키](https://fortune-commit.vercel.app/api?user=YOUR_GITHUB_ID)](https://fortune-commit.vercel.app)
```

| 옵션 | 값 |
| --- | --- |
| `theme` | `dark`(기본) · `light` |
| `lang` | `ko`(기본) · `en` |
| `width` | `495`(기본·최소) ~ `1000`, `full`이면 README 끝까지 (`<img width="100%">`와 함께) |
| `skin` | 쿠키 이름 (해금했거나 산 쿠키만). 도감에서 장착하면 README를 고치지 않아도 바뀝니다 |
| `tz` · `radius` · `hide_border` | 하루가 바뀌는 시간대, 모서리, 테두리 |

### 실행하기

```bash
npm install
npm run dev     # http://localhost:3000 — Redis·GitHub 토큰 없이도 메모리 DB와 가짜 활동으로 로그인 화면까지 볼 수 있음
npm test        # 테스트 97개
```

## 4. 스킬

이번 과제에서 [Claude Code 스킬](https://docs.claude.com/en/docs/claude-code/skills) 5개를 직접 만들어 `.claude/skills/`에 두었습니다. 같은 일을 할 때마다 같은 순서와 규칙으로 하게 만들고, 한 번 겪은 실수를 다시 하지 않게 하려는 목적입니다. 스킬을 쓰다가 맞지 않는 부분을 발견하면 바로 스킬을 고쳤습니다.

### 직접 만든 스킬

#### `todo-log` — TODO를 갱신하고 커밋하는 절차
- **SKILL.md 내용**: ① 처음 계획은 지우지 않고 `[x]` · `[추가]` · `→ [수정]` · `~~삭제~~` · `[테스트 후 변경]`으로 표시 ② 버전 끝 기록란에 날짜·이유 한 줄 ③ 스킬을 쓰면 '스킬 사용 기록'에 남기기 ④ `feat:/fix:/docs:` + 한국어로 커밋 ⑤ **push는 항상 물어보기**
- **어떻게 쓰였나**: 작업이 끝날 때마다 썼습니다. 사용자가 의견을 말하면 그 자리에서 이유와 함께 기록했고, 위 3번의 횟수(수정 43, 테스트 후 변경 27 등)가 이렇게 쌓였습니다.
- **왜 만들었나**: 과제의 'Todo 리스트 변경 내역'은 나중에 기억으로 쓰면 빠지는 것이 많습니다. 바뀔 때마다 같은 형식으로 남기게 해서, README 3번을 TODO_v2에서 그대로 모을 수 있게 했습니다.

#### `figma-to-site` — Figma 화면을 사이트 코드로 옮기는 절차
- **SKILL.md 내용**: 사이트 구조(빌드 없는 HTML·CSS, `site.css` 토큰, `site.js` 공통 부품), **여백 규칙**(카드 안쪽 16px, 쿠키 무대 120px, 바닥 칸 44px 등), Figma 컴포넌트 ↔ 코드 대응표, 옮기기 규칙(토큰 먼저, 쿠키는 그림으로 박지 않기, 기존 동작 유지), **Figma와 비교하는 방법**(PC와 휴대폰 네 폭, 넘침 검사)
- **어떻게 쓰였나**: v3.0-2에서 메인·상점·도감·진열대를 옮길 때 썼습니다. Figma 변수를 먼저 읽어 `site.css`를 같은 이름·값으로 만들고, 섹션마다 Figma 스크린샷을 정답으로 놓고 비교했습니다.
- **고친 것**: 써 보니 '사이트 구조' 설명이 v2(픽셀 쿠키) 기준이었고, '390px 스크린샷'으로는 브라우저 창이 줄지 않아 휴대폰 확인이 안 됐습니다. 컴포넌트 대응표와 '네 폭 iframe 비교'로 고쳤습니다.
- **왜 만들었나**: 실습 과제 때 코드에서 디자인을 여러 번 갈아엎었습니다. 페이지가 여러 개라 매번 같은 방식으로 옮겨야 사이트 전체가 한 디자인처럼 보입니다.

#### `pixel-skin` — 새 쿠키를 만들면 위젯 픽셀까지 자동으로
- **SKILL.md 내용**: ① `make.py`로 벡터 쿠키 그리기(얼굴 금지, 기호는 선으로) ② `to_pixel.py --missing`이 새로 생기거나 바뀐 쿠키만 위젯용 픽셀로 자동 변환(앞 조각·뒤 날개를 나눠 갈라지는 애니메이션 유지) ③ `preview.py`로 벡터·위젯 다크·라이트 확인 ④ Figma에는 PNG로 ⑤ `catalog.json` 등록 → `sync-cookies.mjs`로 사이트·서버에 반영
- **어떻게 쓰였나**: 뽑기 쿠키 10종을 만들 때 스킬 순서대로 진행했고, 레트로 쿠키를 다시 그릴 때도 썼습니다. 처음 `--missing`을 돌렸을 때 `make.py`가 모든 파일을 새로 써서 65개를 다 다시 변환했고, 바뀐 파일만 쓰게 고쳤습니다.
- **왜 만들었나**: 쿠키는 그림이 두 벌(사이트 벡터, 위젯 픽셀)이라, 하나만 고치면 위젯에서만 옛 쿠키가 나옵니다. "새 쿠키가 만들어지면 자동으로 픽셀 변환"하는 흐름을 사용자가 요청했습니다.

#### `fortune-writer` — 운세 문구 규칙과 검수
- **SKILL.md 내용**: 말투(~거예요), 길이, 겁주지 않기, 한국어·영어 같은 번호끼리 같은 뜻, 등급별·특별 운세 규칙, 검사 스크립트 `scripts/check-fortunes.mjs`
- **어떻게 쓰였나**: 검사 스크립트를 지금 문구 145개에 돌려 봤더니 "~거예요. 진짜로요."처럼 뒤에 한마디 붙인 문구 9개가 잘못 걸렸습니다. '문장 끝' 대신 '문장 안에 운세 표현이 있는지'로 규칙을 고쳤습니다. 문구를 300개로 늘리는 v3.1 작업은 아직 하지 않았습니다.
- **왜 만들었나**: 문구 수백 개를 AI가 쓰면 말투와 길이가 흔들리기 쉬워서, 기준과 자동 검사를 먼저 정해 두었습니다.

#### `release-check` — 버전을 마무리할 때 점검·배포
- **SKILL.md 내용**: 남은 일 확인 → 코드 점검(테스트, 보안) → 로컬에서 완성 기준 확인 → push(배포) → **배포된 사이트에서 다시 확인** → 기록
- **어떻게 쓰였나**: 버전의 '완성 기준 점검' 단계에서 쓰는 스킬인데, 아직 끝까지 마무리한 버전이 없어 정식으로 쓰지는 않았습니다. 다만 '배포된 사이트에서 다시 확인' 단계는 매번 따랐고, 그 덕분에 실제 GitHub에서만 나는 질의 버그와 첫 요청 9초 문제를 찾았습니다.
- **왜 만들었나**: 로컬에서 되던 것이 배포에서 안 되는 경우(환경변수, 실제 GitHub 데이터)를 놓치지 않으려고 만들었습니다.
